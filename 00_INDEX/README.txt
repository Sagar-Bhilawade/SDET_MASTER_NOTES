==========================================================
SDET MASTER NOTES - SYSTEM GUIDE
==========================================================

PURPOSE
This folder is the main knowledge base for switch preparation.
It is designed to grow cleanly over time without becoming messy.

HOW THIS SYSTEM WORKS

1. Learn one topic at a time
2. Create one short note file for that topic
3. Keep only high-value final notes
4. Use quick revision files for fast review
5. Use daily logs to track what was revised and what is still weak

MAIN FOLDER MAP

00_INDEX
- System guide
- Topic tracker
- Folder map

01_PLAYWRIGHT
- Main current prep stack
- Basics, framework, API testing, TypeScript, CI/CD, mock questions

02_SELENIUM_JAVA
- Secondary stack for later revision
- Selenium, RestAssured, SQL, framework/build

03_INTERVIEW_PREP
- Self-introduction
- Project stories
- HR answers
- Company-specific notes

04_QUICK_REVISION
- One-page short notes
- Last-minute interview revision

05_DAILY_LOGS
- Daily prep log
- Weak areas
- Interview questions asked

06_RESOURCES
- Official docs links
- Useful references
- Only curated resources, not random dumping

NAMING RULE

Use numbered file names inside each folder.
Example:
01_What_Is_Playwright.txt
02_Why_Playwright_Over_Selenium.txt
03_Browser_Context_Page.txt

NOTE WRITING RULE

Each note should contain:
- What it is
- Why it matters
- Interview answer
- Real project example
- Common questions

IMPORTANT RULES

- Keep notes short and useful
- Do not copy full documentation
- Write in your own language
- Connect every topic back to your actual project
- Update quick revision notes after every 3 to 4 topic files

CURRENT PRIORITY

Current focus is:
01_PLAYWRIGHT

Only after Playwright becomes strong should we expand deeper into:
02_SELENIUM_JAVA
